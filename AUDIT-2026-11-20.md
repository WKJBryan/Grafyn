# Grafyn Repo Audit — 2026-11-20

Six parallel read-only audits (data writes, canvas branch-memory / PR #110, twin store, Vue frontend, website, retrieval/MCP). Load assumed: one user, Tauri app + grafyn-mcp possibly running concurrently, vaults up to thousands of notes. Nothing was changed; all findings are from code reading (the two catastrophic hub findings were spot-verified by a second read; repro tests recommended before fixing #1–#3).

Findings are numbered as in the chat report. Area tags: DATA (write paths), TWIN, CANVAS (PR #110 code), FE (Vue), RET (retrieval/MCP), WEB (website).

## MUST FIX

### 1. [DATA] User note tagged `hub` gets its content replaced by a generated index page
`Note::is_topic_hub()` (`models/note.rs:153-160`) is true for ANY note with tag `hub` (even an inline `#hub` in the body) or title prefix `Hub: `. `sync_topic_hubs` runs `rewrite_hub_note` (`services/topic_hub.rs:198-209`, `:659`) on every registry hub with no `is_auto_topic_hub` gate — the user's note content is replaced by the generated Summary/Subtopics/Members skeleton on the next save of ANY note. Deletion is gated on `is_auto_topic_hub` (`:1321-1326`); the rewrite is not.
**Fix:** gate the rewrite loop + `standardize_existing_hub` persistence on `is_auto_topic_hub(&current)`. Test: note tagged `hub` with body text survives sync byte-for-byte.

### 2. [DATA] Topic-hub sync destroys unparsable frontmatter
`vault_optimizer::prepare_next`, `markdown_migration::apply`, and `backfill_legacy_grafyn_notes` all skip notes with `frontmatter_raw_fallback` set; `topic_hub::persist_if_changed` (`topic_hub.rs:913-947`) does not (zero occurrences of `frontmatter_raw_fallback` in the file), and it runs on every `commit_note_write`. A note with malformed YAML + any topic seed gets `topic_hub_ids` written → `explicit_frontmatter_edit` clears the fallback (`knowledge_store.rs:264-305`) → original frontmatter replaced by defaults (status→draft, custom fields and created_at gone).
**Fix:** skip notes with `frontmatter_raw_fallback.is_some()` in `sync_topic_hubs` (same 2-line guard as the other three callers) + a `MALFORMED_FRONTMATTER_NOTE` test (topic_hub has zero fallback coverage).

### 3. [DATA+RET, found independently by two agents] App startup deletes the search index when grafyn-mcp holds the Tantivy writer lock
`main.rs:97-116`: any `SearchService::new` failure is treated as corruption → `remove_dir_all(search_index)` + retry, else `process::exit(1)`. But `new()` also fails on writer-lock contention (`search.rs:52-54`), which is exactly what happens when Claude Desktop launched grafyn-mcp first (`mcp.rs:71` grabs the writer). Windows: delete half-fails on the open lock file → app refuses to start. macOS/Linux: index wiped under MCP's live writer → two writers → corruption. (`chunk_index` at `main.rs:118-134` has the same pattern, lower exposure.)
**Fix:** distinguish Tantivy `LockFailure` from corruption; on lock failure retry briefly / surface a message; never `remove_dir_all` on a lock error. Verify by repro first (exact tantivy error + Windows file-locking behavior).

### 4. [TWIN] Constitution inference destroys the user's guided-setup priors
`run_constitution_inference` (`commands/twin.rs:283-294`) → `write_auto_constitution_setup` REPLACES values/tastes/constraints/somatic_cues/action_tendencies with distilled template strings (`services/twin/constitution.rs:1148-1164`, gate at `:879-881` fires whenever setup_path exists). Then `prune_stale_setup_constitution_items` (`:1226-1248`) deletes every `guided_setup`-source item whose claim isn't in the distilled set — i.e., ALL user-authored setup items (distilled claims are templates that never match user text). Reachable from existing UI buttons: Save Setup → Run Constitution Inference → typed values gone. Existing test only asserts identity survival.
**Fix:** union distilled entries into existing lists; prune only items with a distinct auto source (e.g. `auto_setup`), never `guided_setup`. Test: user-saved values survive inference.

### 5. [TWIN] Export bundle leaks Private/NoTrain Constitution items and action gaps
Records marked Private/NoTrain are excluded from export (`services/twin/export.rs:104-107`) and their evidence filtered (`:182-226`), but `constitution_items.jsonl` and `action_gaps.jsonl` serialize EVERY item regardless of review status (`:137-148`). A Private-reviewed Constitution item ships its full claim text in the bundle that leaves the machine. (Also: reflection-card evidence packets retain excerpts of later-Private records via `decision_mirror_benchmark.jsonl` — filter at export time if desired.)
**Fix:** filter `ConstitutionStatus::Private | NoTrain` in the two line builders (mirror the record rule) + a test.

### 6. [TWIN] Train/eval/holdout split is unstable → holdout contamination in the external eval
`split_for_record` hashes `id:kind:content:updated_at` with `DefaultHasher` (`export.rs:327-354`). Any edit/soften/re-endorse moves a record between splits across bundles, and `DefaultHasher` is unspecified across Rust releases (toolchain bump reshuffles everything). The external harness's holdout replay then scores trained-on data — measured twin accuracy quietly optimistic and non-reproducible.
**Fix:** hash only `record.id` with a stable inline hash (FNV-1a). Test: same record → same split across exports and after a field edit.

### 7. [TWIN] Never-reviewed items are presented to the model as "Reviewed Constitution"
`constitution_status_from_record` (`constitution.rs:81-91`) creates items directly Active when the source record is AutoPromoted with ≥3 evidence refs — AutoPromoted is machine-assigned (`records.rs:594-599`), no human review. `select_constitution_context` includes every Active item (`:1260`) under the prompt heading "Reviewed Constitution … governing principles" (`context.rs:1078-1087`). Related: every canvas feedback click creates an AutoPromoted record (`commands/twin.rs:498,560,588,619`) flowing into "Approved User Records" and approved/train export with no review, and with 1 evidence ref it never surfaces in the digest for review (`digest.rs:27-43`).
**Fix:** Active only for Endorsed; AutoPromoted-derived items start as Candidate (still in prompt, labeled hypotheses). Feedback-record default → Candidate is a one-enum owner decision.

### 8. [RET] MCP client `limit: 0` panics the server
`TopDocs::with_limit` asserts `limit >= 1` (tantivy 0.22.1). `mcp_tools.rs:490` → `search.rs:199` passes `params.limit` straight through; `recall_relevant` passes `limit * 2` (`memory.rs:26`); Tauri `search_notes` with `Some(0)` same (`commands/search.rs:15`). A malformed tool call from Claude Desktop aborts the MCP server.
**Fix:** `params.limit.max(1)` at the two MCP entry points + `.max(1)` in `SearchService::search`.

### 9. [RET] Panic on multibyte text in claim extraction
`memory.rs:158-162` byte-slices `&title[..100]` — panics on a char-boundary straddle for any accented/CJK/emoji content ≥100 bytes, via the `extract_claims` command.
**Fix:** char-based truncation (`chars().take(100)`).

### 10. [DATA] Mid-apply migration failure leaves a half-rewritten vault with no rollback
`MarkdownMigrationService::apply` (`markdown_migration.rs:225-446`) writes `manifest.json` only at the end (`:423`); every per-note step before it `?`-propagates. Failure on note 51 of 200 (transient file lock) → no manifest → `rollback(run_id)` can't load, `status()` says "previewed", 50 notes stay rewritten. Backups ARE on disk (`runs/<id>/backups/`) but unreachable from the app.
**Fix:** persist the manifest incrementally (status `in_progress` before the loop, update per note, flush `failed` on error). Test: fail note 2 of 3, assert rollback restores note 1.

### 11. [FE] Cross-session tile/debate injection on session switch
`tile_created` (`stores/canvas.js:506-509`) and `debate_created` (`:838-841`) push into `currentSession` without checking it is still the origin session. Send in A, click B before TileCreated arrives → A's tile renders in B and `mergeSavedSession` (`:161`) keeps it forever.
**Fix:** `if (!currentSession.value || currentSession.value.id !== sessionId) return` in both handlers (guard already exists in `applyWorkingMemoryUpdate`, `:219`). Related: `debate_complete` does an unconditional `loadSession(sessionId)` (`:883`, `:965`) that yanks the user back to an abandoned session — same guard.

### 12. [FE] Hardcoded 120s/180s total-duration stream timeouts truncate long generations
`waitForModelsComplete(keys, 120000)` (`canvas.js:548/1068/1130`; 180s debates `:893/974`) resolves on TOTAL duration; on timeout the listener (which also carries `session_saved`) is removed — the tile freezes mid-answer in 'streaming' status and the backend's final save is never reconciled. xhigh-reasoning + web-search runs routinely exceed 2 min.
**Fix:** make it an idle timeout — reset the deadline whenever any key saw a chunk (track `lastActivity` in `applyChunk`).

## SHOULD FIX

### 13. [CANVAS — PR #110 follow-ups] Four bugs in the new branch-memory code
(a) **Incremental compile dead on linear chains**: `prepare_branch_compact` looks up `previous` only at the exact parent key (`working_memory.rs:731-736`) but dreams are written at that key and never propagated — once over threshold, EVERY follow-up fires a full-chain compile (unbounded input, blocking before TileCreated, up to 60s). Fix: seed `previous` from the preceding turn's key; on Reuse from the seeded key also persist at the parent key.
(b) **Stale dreams survive deletion**: `delete_tile`/`delete_response` (`canvas_store.rs:225-273`) never prune `branch_memories` — deleted content leaks back via the dream; unbounded growth. Fix: retain only keys whose tile prefix still exists.
(c) **Threshold clamp not enforced on load**: clamp applied in `SettingsService::update` only; `context.rs:175-178` uses the raw on-disk value (hand-edited 100 → compile every turn; 10M → compaction off). Fix: clamp at the read site.
(d) **estimate_tokens undercounts non-whitespace text**: `split_whitespace().count()*4/3` (`working_memory.rs:588-590`) counts a minified-JSON/CJK blob as ~2 tokens — compaction never fires for the heaviest sessions. Fix: `max(words*4/3, chars/4)+1`.
Also (e) minor: dream + full transcript both sent when a dream exists but the chain is under threshold (`working_memory.rs:179-181` vs `:134-143`). Missing tests for (a)–(c).
**Note:** #110 also FIXES a main-branch bug — on main the twin prompt reads `session.working_memory`, which production never writes (`context.rs:476` on main), so the twin never got the dream; the branch's `prefix_twin_prompt_with_memory` (`context.rs:490`) corrects this. Merge #110, then fix (a)–(e) as a follow-up.

### 14. [RET] Every note save is O(entire vault)
One save → `sync_topic_hubs` reads+parses every file (`topic_hub.rs:103`), full graph rebuild (`commands/mod.rs:168`), link-discovery `bootstrap` runs YAKE over EVERY note with an unconditional atomic JSON write per note (`link_discovery.rs:220-257,755-762,1107-1136`), plus `refresh_cache()` full vault walks in `create_note`/`update_note` (`knowledge_store.rs:104-156,229-234,325`); GraphIndex "incremental" methods do full rebuilds (`graph_index.rs:242-251`). 5,000-note vault: seconds of latency + ~5,000 file writes per keystroke-save; a 200-item MCP import repeats the graph rebuild 200× (`mcp_tools.rs:677`).
**Fix (cheapest):** skip `build_profile`/`persist_note_record` when `content_hash` unchanged; stop re-running discovery/optimizer bootstrap per save; make GraphIndex `update_note` patch only affected edges.

### 15. [RET+DATA] Two-process desync family (app + grafyn-mcp)
(a) App holds writer → MCP `create_note`/`update_note` silently skip indexing (`let _ =` at `mcp_tools.rs:385`): note unsearchable in BOTH processes until manual reindex. (b) MCP `delete_note` leaves ghost docs in search AND the deleted note's chunks keep serving canvas/twin context until app restart (`mcp_tools.rs:457-480`; chunk side not covered by the documented scope decision). (c) MCP `list_notes`/backlinks serve a startup snapshot (`mcp.rs:98-110`) while `search_notes` reloads cross-process — stale + fresh mixed. (d) Duplicate note_id across processes: `generate_note_id` dedupes only against the per-process cache (`knowledge_store.rs:440-459`) → two files with one id; `path_index` last-wins (`:131`) → wrong-note updates/deletes.
**Fixes (cheapest honest):** warn in MCP tool results when `search.is_readonly()`; drop chunks whose `parent_note_id` no longer resolves at the retrieval boundary; mtime-check + refresh before list/backlink serves; disk-existence check in `generate_note_id`.

### 16. [TWIN] `run_twin_inference` silently reverts user edits to reviewed records
When an inference key matches, the run overwrites kind/content/evidence/confidence even for Endorsed or Private/NoTrain records — only `promotion_state` is protected (`records.rs:604-641`). An endorsed-then-edited record resets to the template while staying Endorsed.
**Fix:** skip content overwrite unless Candidate/AutoPromoted.

### 17. [DATA] `update_note` with changed `relative_path` silently overwrites another note's file
No collision check in `update_note_with_options` (`knowledge_store.rs:279-314`) — `write_note_file` renames over the target. Reachable via raw IPC and internal rollback callers with historical paths; policy is backend enforcement.
**Fix:** error when the normalized new path exists and isn't the note's own file (~5 lines + test).

### 18. [RET] Wikilink resolution: duplicate titles flip nondeterministically; code fences create phantom edges
(a) `rebuild_from_cached_notes` iterates HashMap order with last-wins `title_to_id` (`graph_index.rs:76-78`) — two notes titled "Meeting Notes" re-point every backlink arbitrarily on each rebuild; KnowledgeStore uses first-wins (`:135`), so the two resolvers disagree. (b) Wikilink regexes run over raw content (`knowledge_store.rs:19-25,377-411`) — fenced code creates real graph edges (hashtags DO strip fences; `link_discovery` has `clean_markdown` to reuse).
**Fix:** deterministic ordering + `or_insert` in the graph rebuild; run extractors over fence-stripped content.

### 19. [WEB] Windows ARM64 users always get the x64 installer
`navigator.userAgentData?.architecture` is read synchronously (`website/src/scripts/download.js:20-23`) but it's a high-entropy hint only available via `await getHighEntropyValues(['architecture'])` — always undefined; the UA-regex fallback never matches (frozen UA says x64). The native arm64 installer is unreachable from the primary CTA.
**Fix:** make `detectPlatform` async with `getHighEntropyValues`, await in `renderCta`. Related [WEB]: GitHub API is polled on every page (imported in the Base layout, `main.js:1`) every 90s with TTL==interval (`download.js:206-212`, `github.js:6`) — two idle tabs exceed the 60/hr anonymous rate limit and break the download page. Fix: bail when no `[data-download-cta]` on the page; TTL/refresh → ~10 min.

### 20. [FE] Concurrent debates corrupt each other's streams
Debate handlers process every debate event in the session (`canvas.js:860-871,937-954`): chunks appended once per listener (doubled text), `removeStreaming` over-decrements (indicator clears early), continueDebate's `round_start` resets the OTHER debate's streaming state (closure-keyed write without `data.debate_id` check). The Debate button stays enabled during streaming (`CanvasContainer.vue:293-299`).
**Fix:** guard every debate handler by its own debate id (same pattern as sendPrompt's own-tile buffer).
